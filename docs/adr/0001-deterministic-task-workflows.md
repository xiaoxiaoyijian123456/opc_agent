# 用确定性任务模板约束多角色协作

MYOPC 需要让角色顺序、PRD 审批和失败暂停可验证，而不是依赖模型自觉遵守提示词。决定由系统按任务类型执行固定模板：通常为 `PM → Dev → Tester → Admin`，视觉任务在 Dev 前插入 UI；保留用户手动分发作为独立高级入口。相比纯提示词自由编排，这一选择牺牲部分灵活性，换取核心路径的可审计、可测试与可恢复性。

`orchestrator` 是标准任务流、角色依赖、PRD 阻塞和失败暂停的唯一所有者。Brain 负责意图识别、问答和生成，不拥有绕过或重排标准流程的执行权。

PM 通过结构化 `requires_ui` 提出视觉流程判定，orchestrator 在 PRD 审批时展示并冻结模板；无效判定不得被静默转换为默认流程。
